# v0.2.1 Catalog + Offer Search Performance

**Date:** 2026-05-07
**Branch:** feat/v0.2.1-catalog-offer-search
**Commits:** Merges audit branch + catalog/offer search changes

## Summary

v0.2.1 replaces the slow Meilisearch-dependent search path with a fast PostgreSQL catalog+offer search engine (`runCatalogOfferSearch`). When `MEILI_ENABLED=false` (the intended production default), search requests skip Meilisearch entirely and query the database directly using tiered CTE ranking, completing in milliseconds instead of 30+ seconds.

## Architecture Changes

### Search Path (MEILI_ENABLED=false, default)

1. `GET /api/search` → `runCatalogOfferSearch()`
2. Two-path PostgreSQL query:
   - **Supplier-backed path**: Products with approved supplier mappings, ranked by CTE tier
   - **Catalog-only path**: Products without mappings, max 30 results
3. Results mapped to `SearchHit` with availability status and CTA
4. Fallback when MEILI_ENABLED=true but Meili unavailable: also uses `runCatalogOfferSearch()`

### Availability Status Model

| Status | CTA (TR) | CTA (EN) |
|--------|----------|----------|
| PURCHASABLE | Sepete Ekle | Add to Cart |
| REQUEST_PRICE | Fiyat Al | Request Price |
| VERIFY_FITMENT | Uygunluk Sor | Verify Fitment |
| OUT_OF_STOCK | Stok Gelince Haber Ver | Notify When Available |

### Catalog-First Principle

- All known parts remain visible regardless of price/stock
- Products with supplier-backed pricing are ranked higher
- Products without price show "Fiyat Al" CTA (no dead ends)

## Remaining Production Risks

1. **Search results empty in local testing** — Local DB has minimal data. Production DB will have actual supplier products. The query logic is covered by 31 unit tests but needs production verification with real data.

2. **pg_trgm indexes** — The `scripts/search-indexes.sql` recommendations should be applied to production for optimal performance. Without them, ILIKE queries will use sequential scans.

3. **MEILI_ENABLED must be false** — If set to true without a running Meilisearch instance, the health check timeout (3s) still applies before falling back to catalog search. Setting it to false skips Meili entirely.

4. **NEXT_PUBLIC_ALLOW_INDEXING** — Must be set to `true` in production env **after** deployment and smoke/performance validation on VPS. Do not enable before validation.

5. **Redis unavailable in local** — Health check reports `redis: unavailable`. Production needs Redis for caching. Search responses will not be cached without Redis.

## Required Production Env Vars

```bash
# Must be set before deployment
MEILI_ENABLED=false
```

4. Deploy to VPS via CI/CD
5. Wait for container healthy
6. Run `curl -s https://getirbakim.com/api/health | python3 -m json.tool`
7. Run `bash scripts/audit-production-performance.sh`
8. If performance is acceptable, set `NEXT_PUBLIC_ALLOW_INDEXING=true` in `.env.production`
9. Rebuild and redeploy for indexing to take effect
